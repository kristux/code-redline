code-redline is a local code review server at http://localhost:7890.

Workflow:
1. Generate a full patch from the base branch:
   git diff $(git merge-base HEAD main) > review.patch
2. Create a review:
   curl -X POST http://localhost:7890/reviews -F "file=@review.patch"
   Response: {"id": "abc123", "url": "/reviews/abc123", ...}
3. Developer opens the URL and adds inline comments in the browser.
4. Read comments:
   curl http://localhost:7890/reviews/abc123/comments
5. Action each unresolved comment in the codebase.
6. Mark comments resolved:
   curl -X PATCH http://localhost:7890/reviews/abc123/comments/{cid} \
     -H "Content-Type: application/json" \
     -d '{"resolved": true, "resolution_note": "Refactored as suggested"}'
7. Upload a new revision (full diff again, not incremental):
   git diff $(git merge-base HEAD main) > review.patch
   curl -X POST http://localhost:7890/reviews/abc123/revisions -F "file=@review.patch"

Patch convention:
- Every patch must be a full diff from the base branch, never incremental.
- New files are included as long as they are tracked (git add).

API:
  POST   /reviews                        Create review, returns {id, url}
  GET    /reviews/{id}/comments          Full review.json with all comments
  POST   /reviews/{id}/comments          Add a comment
  PATCH  /reviews/{id}/comments/{cid}    Resolve/unresolve (fields: resolved, resolution_note)
  DELETE /reviews/{id}/comments/{cid}    Delete a comment
  POST   /reviews/{id}/revisions         Upload a new revision patch

What it is

A local code review server running at http://localhost:7890. Developers upload patch files and add inline comments in the browser. Agents read those comments, action them in the codebase, and upload a revised patch.

Workflow

# 1. Generate a full patch from the base branch
git diff $(git merge-base HEAD main) > review.patch

# 2. Create a review
curl -X POST http://localhost:7890/reviews -F "file=@review.patch"
# → {"id": "abc123", "url": "/reviews/abc123", ...}

# 3. Developer opens the URL and adds inline comments

# 4. Read the comments
curl http://localhost:7890/reviews/abc123/comments

# 5. Action each unresolved comment in the codebase

# 6. Mark comments resolved
curl -X PATCH http://localhost:7890/reviews/abc123/comments/c1a2b3c4 \
  -H "Content-Type: application/json" \
  -d '{"resolved": true, "resolution_note": "Refactored as suggested"}'

# 7. Upload a new revision (full diff again, not incremental)
git diff $(git merge-base HEAD main) > review.patch
curl -X POST http://localhost:7890/reviews/abc123/revisions -F "file=@review.patch"

Patch convention

Every patch — initial and revised — must be a full diff from the base branch, not an incremental diff from the previous revision.

git diff $(git merge-base HEAD main) > review.patch   # correct
git diff HEAD > review.patch                          # wrong — last commit only

New files are included as long as they are tracked (git add). Untracked files will not appear in the diff.

Comment schema

{
  "id":              "c1a2b3c4",
  "revision":        1,
  "file":            "path/to/file.py",
  "line":            45,
  "line_content":    "    the actual line of code",
  "comment":         "reviewer's comment text",
  "resolved":        false,
  "resolved_at":     null,
  "resolution_note": null    // optional — add when resolving
}
